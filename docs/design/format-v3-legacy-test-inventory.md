## Liveness audit after the native admission regression

The earlier replacement matrix mapped checkpoint safety to generic recovery
controls. That did not test the *binding* of the common admission controller to
v3 occupancy. The production closure was therefore incomplete: the legacy writer
remained at zero and no test crossed the default ring while relying on automatic
pressure relief. Codec, manual-flush and safety tests could all pass.

The audit inspected the retained legacy constructor inventory and storage tests
using admission, pressure, throttling, `errWALFull`, wait/timeout and stalled-flusher
paths. The five concrete retained controls above now name their native counterparts:
`TestFlusher_AdvancesCheckpointBeforeReadFromExtent`,
`TestFlusher_ReleasesWALPressureAfterCheckpoint`,
`TestWALWriterReuseIsBoundedByTheDurableTail`,
`TestWALWriterBatchReuseIsBoundedByTheDurableTail`, and
`TestWALStoreRecoverBoundsPersistFailureRefusesAppendsUntilRetry`.
The last three include safety gates needed to make reuse liveness safe; v3's
sticky persistence failure intentionally requires physical reopen rather than
v2's same-instance retry. These are not claimed to have identical retry semantics.
`TestWriteExtentDirectSupersedesPriorDirtyWAL` also mentions pressure, but tests
BASE supersession, not admission; its existing install/map mapping stays intact.
Raw writer controls remain format-specific; no test is removed.

| Behaviour | Native-v3 control | Scope |
| --- | --- | --- |
| Healthy burst and automatic pressure relief | `TestWALStoreV3AdmissionBurstFiveRings` | Fresh mapped 64 KiB ring, five ring sizes of writes, Sync every ten blocks, real automatic flusher, all submitted bytes read back; legacy-sampler mutant must fail this test |
| Production default geometry and frontend Flush | `TestWALStoreChunkV3_SequentialBurstFlush` | Public provider, 64 MiB WAL, 320 MiB via NVMe handler, periodic Flush and literal-byte readback |
| Occupancy and checkpoint pressure reset | `TestWALStoreV3AdmissionUsesNativeOccupancy` | Actual append size and both-slot released floor, not a mocked pressure value |
| Soft-watermark throttling | `TestWALStoreV3AdmissionSoftThrottles` | Real occupied v3 ring drives a positive bounded soft delay; only sleep is recorded |
| Hard watermark, stopped flusher, timeout and resumed progress | `TestWALStoreV3AdmissionStallDeadlineAndResume` | Native occupied ring, bounded timeout, waiter remains blocked until actual checkpoint/reclaim then resumes |
| Close during pressure | `TestWALStoreV3AdmissionCloseEndsPressureWait` | Closed pressured store refuses with the typed close error rather than admitting |
| Idle/admission rollover without a new checkpoint | `TestWALStoreV3ReclaimRolloverProgressWithoutNewCheckpoint` | Both single/batch admission triggers plus idle and unchanged-checkpoint paths |
| Flusher persistence fault | `TestWALStoreV3_AutomaticMapPersistenceFailureLatchesStore` | Real owned-map failure latches the store; no false progress or unsafe admission |

There were no dedicated `walAdmission` unit tests in the retained v2 suite for
soft delay, hard-wait timeout or stopped-flusher resumption. Those gaps are covered
by the new native tests rather than reported as already covered. The new small-ring
tests use the production engine, controller and flusher with test-only geometry;
they do not replace the public default-size provider control. They preserve the
existing bounded admission policy, not a reservation guarantee for oversized or
concurrently pre-admitted batches, or a promise that an entirely unsynced ring can
reclaim unacknowledged bytes.
