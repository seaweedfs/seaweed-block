# v0.2 Alpha — Day-1 Activation And First Volume

## Summary

Seaweed Block v0.2 alpha packages the previously proven block, CSI, recovery,
and observation work into a user-facing Kubernetes Day-1 loop:

```text
activate stack
-> create first PVC-backed volume
-> writer pod verifies data
-> reader pod verifies persisted data
-> collect product-owned cluster evidence
-> generate a local read-only status report
-> cleanup leaves no sessions or product processes
```

This is the first alpha release boundary where a PM, QA engineer, or early
operator can follow a single tutorial and reach a verified first PVC without
reading source code.

## User-Visible Additions

- `scripts/activate-k8s-alpha.sh` runs preflight, installs the alpha stack,
  waits for blockmaster/CSI readiness, creates the StorageClass, and writes an
  activation summary.
- Multi-node activation automatically uses non-loopback iSCSI/status addresses
  and CHAP for the Day-1 path.
- `scripts/run-basic-app-example.sh` creates the example PVC, runs writer and
  reader checksum pods, collects status/inventory evidence, generates a local
  report, and cleans the example resources.
- `sw-block ops report` renders a local static read-only HTML report backed by
  product-owned cluster evidence and event timeline data.
- Published-image mode supports immutable GHCR tags such as
  `ghcr.io/seaweedfs/seaweed-block:sha-<commit>` and
  `ghcr.io/seaweedfs/seaweed-block-csi:sha-<commit>`.

## Validated User Path

```bash
bash scripts/activate-k8s-alpha.sh "$PWD"
bash scripts/run-basic-app-example.sh "$PWD"
cat "$(ls -td /tmp/sw-block-basic-app-* | head -1)/first-volume-summary.txt"
```

```text
first_volume_status=ok
pvc_phase=Bound
writer_verified=true
reader_verified=true
inventory_status=ok

cleanup_status=ok
```

## Current Claim

Seaweed Block v0.2 alpha provides an install-to-first-volume Kubernetes loop:

- install the alpha stack on a supported k3s/Kubernetes lab,
- create a PVC-backed block volume through Kubernetes,
- write and read data through app pods,
- inspect cluster, volume, replica, primary, frontend, and event evidence,
- collect a local read-only status report,
- uninstall and leave the lab clean.

## Explicit Non-Claims

- Not production-ready.
- No Helm chart or operator lifecycle yet.
- No hosted dashboard; `sw-block ops report` is a static local read-only
  report.
- No backup, snapshot, or restore workflow.
- No upgrade/rollback safety claim.
- No mutating admin workflows such as promote, repair, rebuild, failback, or
  delete buttons.
- No broad performance, RTO, or compatibility SLO.
- No transparent Kubernetes node-loss failover without pod recreate in the
  Day-1 quickstart.
- No NVMe ANA parity for the transparent failover path.

## Release Validation Guidance

For QA/PM release validation, prefer immutable published images:

```bash
export SW_BLOCK_ACTIVATION_IMAGE_MODE=published
export SW_BLOCK_IMAGE=ghcr.io/seaweedfs/seaweed-block:sha-<commit>
export SW_BLOCK_CSI_IMAGE=ghcr.io/seaweedfs/seaweed-block-csi:sha-<commit>

bash scripts/activate-k8s-alpha.sh "$PWD"
bash scripts/run-basic-app-example.sh "$PWD"
```

Use mutable `:alpha` only as a casual smoke tag; it can drift from the source
tree unless the publish commit is known.
