# v0.3 Alpha — Helm Install And Observable First Volume

## Summary

Seaweed Block v0.3 alpha promotes the Kubernetes Day-1 path from script-first
activation to Helm-first activation for supported lab clusters.

The release boundary is:

```text
generate Helm values
-> helm install Seaweed Block
-> create the first PVC
-> writer pod verifies data
-> reader pod verifies persisted data
-> inspect read-only report/dashboard evidence
-> helm uninstall + host cleanup verification
```

This is still an alpha release. It is meant for supported k3s/Kubernetes labs,
PM/QA evaluation, and early technical feedback. It is not production-ready.

## User-Visible Additions

- Helm chart under `charts/seaweed-block`.
- `sw-block ops generate-helm-values` generates a Day-1 values file from the
  current Kubernetes cluster.
- Single-node values use loopback mode for laptop/dev labs.
- Multi-node values use non-loopback node InternalIPs, external iSCSI/status,
  and CHAP by default.
- `sw-block ops report` writes static read-only artifacts:
  - `index.html`
  - `cluster-evidence.json`
  - `timeline.jsonl`
  - `summary.txt`
- `sw-block ops dashboard` serves the same evidence locally over HTTP.
- Helm first-volume gates validate writer/reader data and cleanup.

## Validated User Path

Generate values:

```bash
sw-block ops generate-helm-values --out values.day1.yaml
```

Install:

```bash
helm install sw-block charts/seaweed-block \
  --namespace kube-system \
  --create-namespace \
  -f values.day1.yaml \
  --wait
```

Run the first-volume check:

```bash
SW_BLOCK_INSTALL_MODE=helm \
SW_BLOCK_HELM_RELEASE=sw-block \
SW_BLOCK_HELM_NAMESPACE=kube-system \
SW_BLOCK_HELM_VALUES_FILE=values.day1.yaml \
  bash scripts/run-basic-app-example.sh "$PWD"
```

Inspect the report:

```bash
APP_DIR="$(ls -td /tmp/sw-block-basic-app-* | head -1)"
cat "$APP_DIR/status/report/summary.txt"
```

Optionally serve the dashboard from the collected evidence:

```bash
sw-block ops dashboard --from-bundle "$APP_DIR" --listen 127.0.0.1:9334
```

## Expected Evidence

The first-volume summary should include:

```text
first_volume_status=ok
pvc_phase=Bound
writer_verified=true
reader_verified=true
inventory_status=ok
status_report=status/report/index.html
cleanup_status=ok
```

The report directory should include:

```text
index.html
cluster-evidence.json
timeline.jsonl
summary.txt
```

## Image Guidance

For QA/PM/release validation, use immutable images:

```text
ghcr.io/seaweedfs/seaweed-block:sha-<commit>
ghcr.io/seaweedfs/seaweed-block-csi:sha-<commit>
```

Mutable `:alpha` is a smoke/demo tag only. It can drift from the source tree and
must not be used as release proof unless the publish commit is known.

## Current Claim

Seaweed Block v0.3 alpha provides a Helm-based Kubernetes first-volume loop:

- generate cluster-aware Helm values,
- install the alpha stack with Helm,
- create a PVC-backed block volume through Kubernetes,
- verify writer/reader data,
- inspect read-only report/dashboard evidence,
- uninstall and verify cleanup.

## Explicit Non-Claims

- Not production-ready.
- No operator lifecycle or CRDs.
- No mutating admin UI workflows such as promote, repair, rebuild, failback,
  backup, restore, or delete.
- Cleanup remains a scripted/TestOps path, not a dashboard button or operator
  workflow.
- No backup, snapshot, or restore workflow.
- No upgrade/rollback safety claim.
- No broad distro/kernel/initiator compatibility matrix.
- No performance, RTO, or SLO claim.
- No new recovery scope beyond the previously gated RF3 recovery, node-loss,
  and Stage 2 multipath evidence.
- No production hosted dashboard; the dashboard is local, read-only, and alpha.

## Validation Required For Close

The release closes only when both gates pass:

- `testops/scenarios/helm-single-node-first-volume-chain.yaml`
- `testops/scenarios/helm-first-volume-chain.yaml`

The close report must cite the run IDs and confirm:

- Helm values generation,
- Helm install readiness,
- PVC Bound,
- writer/reader checksum,
- report/dashboard consistency,
- immutable image/digest evidence where applicable,
- cleanup hygiene.
