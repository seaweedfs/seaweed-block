# v0.1 Alpha — Kubernetes Block Foundation

## Summary

Seaweed Block v0.1 alpha established the Kubernetes block-storage foundation:
PVC provisioning through CSI, product-owned blockvolume lifecycle, read-only
inventory, recovery gates, and protocol-level failover evidence.

This version is an engineering alpha. It proves that the core storage/control
plane can work under gated lab scenarios. It is not yet a polished Day-1 user
installation experience.

## What Users And Reviewers Can Evaluate

- Dynamic PVC provisioning through the Seaweed Block CSI driver.
- Product-owned generated `blockvolume` Deployments instead of manual
  generated-YAML apply steps.
- Read-only `sw-block ops inventory` evidence for volumes, replicas, primary,
  frontends, and issue lines.
- Durable local restart/reattach for the supported alpha path.
- Multi-node attach/placement visibility and explicit loopback non-claims.
- RF=2 safe-refusal and controlled best-effort demo recovery.
- RF=3 `sync-quorum` mounted recovery through CSI/pod recreate.
- iSCSI ALUA + Linux dm-multipath transparent mounted failover on the gated
  alpha path.
- Kubernetes node-loss recovery through CSI/pod recreate on a surviving node.
- Product-owned control-plane event evidence for placement, candidate
  evaluation, authority publication, and CSI reattach.

## Explicit Non-Claims

- Not production-ready.
- No one-command Day-1 activation loop yet in this release boundary.
- No Helm chart or operator lifecycle.
- No hosted dashboard.
- No backup, snapshot, or restore workflow.
- No upgrade/rollback safety claim.
- No mutating admin workflows such as promote, repair, rebuild, failback, or
  delete buttons.
- No broad performance, RTO, or compatibility SLO.
- No NVMe ANA parity for the transparent failover path.

## Upgrade Note

Use v0.2 alpha if the goal is to evaluate the first user-facing Kubernetes
install-to-first-volume loop. Use v0.1 alpha only as the reference boundary for
the underlying storage, CSI, recovery, and observation capabilities.
