# Read-Only Operator Foundation Contract

Status: Phase 32 D2 alpha contract.

Purpose: define the first operator-consumable status artifact without claiming
a production Kubernetes operator or any mutating storage action.

## Boundary

This contract is read-only.

Allowed:

- project `ClusterEvidence` into a Kubernetes-native operator snapshot,
- expose ManagedVolume Conditions, Events, and allowed read-only/dry-run actions,
- publish the CRD/Condition/Event contract that a future operator can implement,
- serve the same snapshot from `sw-block ops report` and `sw-block ops dashboard`.

Not allowed:

- promote,
- repair,
- rebuild,
- fail back,
- delete storage,
- clean up live storage state,
- mutate authority, CSI attachment, or host-path state.

## Artifact

`sw-block ops report` writes:

```text
operator-snapshot.json
```

The dashboard serves the same data at:

```text
/operator-snapshot.json
```

The artifact is generated by:

```text
BuildOperatorFoundationSnapshot(ClusterEvidence)
```

Code:

- `core/ops/operator_snapshot.go`
- `core/ops/operator_snapshot_test.go`

## Shape

Top-level fields:

- `api_version`: `block.seaweedfs.com/v1alpha1`
- `kind`: `ReadOnlyOperatorFoundationSnapshot`
- `read_only`: always `true`
- `mutation.mutation_allowed`: always `false`
- `mutation.allowed_modes`: `read_only`, `dry_run`
- `crd_contract`: output of `ManagedVolumeCRDContractDefinition`
- `cluster`: aggregate status counts and cluster Conditions
- `volumes`: `ManagedVolumeOperatorContract` entries

Phase 32 adds:

- `crd_contract.read_only=true`
- `crd_contract.rbac.mutating_storage_verbs_allowed=false`
- `crd_contract.rbac.allowed_verbs=get,list,watch,update_status,patch_status,create_event`
- `cluster.stale_volume_count`
- cluster `EvidenceStale=True` when any ManagedVolume has stale evidence

The snapshot is deliberately close to a Kubernetes operator status model, but it
is not a CRD instance yet. It is the bridge between current CLI/report/dashboard
evidence and a future status-only operator.

## Fact Flow

```text
Participants
  -> Fact Authorities
  -> ClusterEvidence
  -> ManagedVolumeProjection
  -> ManagedVolumeOperatorContract
  -> ReadOnlyOperatorFoundationSnapshot
```

The snapshot does not derive new truth from logs. It consumes normalized product
evidence and projects it into the operator-facing contract.

## Conditions And Events

Volume Conditions and Events come from the ManagedVolume operator contract.

Examples:

- `Ready=True reason=first_volume_verified`
- `Blocked=True reason=publish_target_loopback_cross_node`
- `Recovered=True reason=transparent_host_path_recovered`
- `EvidenceStale=True reason=evidence_stale`
- `Warning reason=csi_node_image_pull_failed`

The same reason codes must appear in:

- support bundles,
- `sw-block ops explain`,
- `sw-block ops report`,
- dashboard JSON,
- future CRD status.

## Tests

Scoped regression coverage:

- `go test ./core/ops`
- `go test ./cmd/sw-block`

Specific checks:

- operator snapshot is always read-only,
- blocked volumes carry warning events and stable reason codes,
- stale evidence volumes carry `Ready=Unknown`, `EvidenceStale=True`, and
  warning events,
- cluster status counts `stale_volume_count`,
- report writes `operator-snapshot.json`,
- dashboard serves `/operator-snapshot.json`,
- CLI output names the operator snapshot artifact.

## Non-Claims

D11 does not ship a controller manager, CRD install, reconcile loop, RBAC
manifest, metrics endpoint, mutating action, repair workflow, or production
operator lifecycle.

Those belong after the status model, CRD contract, and read-only projection stay
stable across productized operations gates.
